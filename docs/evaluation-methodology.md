# 评测方法论

## 评测对象

评测同时观察最终回答和执行过程。部分 Case 只判断回答，部分 Case 还要求检查 Trace、工具调用、时间边界和 KYC 访问。

## 评测器

配置包含九类评测器：规则与红线、事实与证据、KYC 使用、风险与适当性、任务完成度、过程行为、反事实成对、热点上下文、隐私与最小必要数据。

## 最终裁决

裁决优先级来自 `evaluator_config_v2.json`：

1. P0 override rule
2. critical evaluator failure
3. P1 evaluator failure
4. P2 issue aggregation

任一 P0 一票否决或 P0 关键评测失败时结果为 `BLOCK`。分数仅作辅助展示，不覆盖一票否决和关键评测结果。

## 人工复核

仅在评测器冲突、P0/P1 低置信度或新型 Bad Case 时触发。人工可接受或驳回自动判定、修改严重等级、标记新失败模式并加入回归集。

## 用户反馈

点踩、重复追问、快速退出、数字错误和答非所问等信号只形成 Feedback Candidate。未经复核的反馈不能直接改变 Release Gate。

## 事实与个性化

客观事实不能随画像变化；建议层需要在相关 KYC 约束下变化。G16 检查“建议是否真的变化”，G22 检查“事实查询是否读取了不必要画像”。
